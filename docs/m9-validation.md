# M9 validation — Plot Threads integration and narrative Guide

M9 extends the existing M8 Story Plot. **M10 has not been started.** Work and native validation performed on **30 October 2026**, Linux, with isolated Obsidian profiles and disposable vaults. Historical M8 changes were already present and uncommitted at the start; they were retained.

## 1. Functionality

Story → Plot now includes a collapsible Plot Threads panel. It discovers current-Workspace `plot-thread` Entities, supports native creation, generic Focus, searchable/paged choices, multi-thread selection and explicit Highlight / Filter modes. A Scene’s action menu opens inline association controls. A Scene may have zero, one or several Threads. Up to two names and a `+N` count keep Scene rows compact; a tooltip and screen-reader text retain the full names.

Selected Threads show their associated Scenes across Sections in canonical narrative order. Unplaced members remain separate, without invented positions. Scene Focus and Write use the existing native navigation; Thread Focus uses the same generic entity editor. There is no separate editor or second Plot Board. Existing Plot drag, movement, Section creation and writing remain available, including movement while filtering. Empty Sections under a filter say “No matching scenes.”

## 3. Existing APIs and components reused

`createEntity` through the existing StoryCreateDialog creates ordinary Thread notes. The PlotService remains responsible only for Scene/Section placement; creating a Thread from Plot takes the generic creation path. EntityRelationWriter `addRelation` / `removeRelation`, RelationTypeRegistry validation, relation mappers, repository metadata queue, `processFrontMatter`, stale relation checks and index refresh remain the only relationship persistence path.

`projectPlot`, EntityIndex snapshots, Story collections, generic Focus / Back origin, native Markdown opening, native Scene action Menu and shared `paginateInbox` / InboxPagination are reused. The existing Guide Modal and topic navigation receive one additional topic rather than a new documentation system.

## 4. Domain, persistence and compatibility

No new Entity type, relation kind, schema, `bs_story` fields, membership database or configuration version. Configuration remains **v8**. No migration or automatic enabling of Story/types occurs. Existing custom `plot-thread` definitions keep M7’s compatibility policy. All statuses remain discoverable, as in M7/M8.

The optional generic `RelationWriteScope` contains expected Workspace, source type and target type. Plot associations supply it to prevent stale contextual writes from creating cross-Workspace or changed-type links at commit. Existing generic callers omit it and keep the established universal/custom cross-Workspace rules. This is a small guard inside the existing adapter, not a second persistence API.

Relation edits keep the existing `bs_updated` timestamp behavior. They do not alter narrative ranks, unknown neighboring metadata, properties, schema values, unrelated relations or Markdown bodies. Untouched Scene files are not rewritten. A successful write refreshes from Markdown; rejected mutations also refresh through the repository’s existing `finally` path. External Markdown changes flow through the normal cache/index synchronization.

## 5. Membership semantics

A **Related to** link between a Scene and a Plot Thread in the **same Workspace** constitutes membership. Either direction is readable, because Focus can create either existing directed link. New association writes Scene → Related to → Thread. If either direction already exists, Add does not create a redundant reverse edge. Duplicate same-direction requests remain rejected by the canonical relation mapper at commit.

Supports, Depends on, Originated from, Alternative to and custom relation kinds keep their current meaning and are not silently reinterpreted as membership. This explicit convention avoids inventing a new required relation schema or guessing the intent of existing custom links. Users can continue to manage those links in generic Focus.

Remove deletes only the matching Related to edges for the chosen pair. Both Entities and all other associations remain. If manually authored opposite links both exist, removal performs two ordinary source-owned writes. A failure reports `Removed X of Y related links` and the actual remaining membership stays visible. There is no global transaction/rollback promise. Missing or invalid references produce a neutral unavailable-related-link hint; the UI cannot infer that every missing UUID used to be a Thread. Focus remains the repair surface. Cross-Workspace relationships remain available in generic Focus but do not appear as local Thread membership.

## 6. Canonical order and viewing state

Progression consumes the existing `projectPlot` Section/Scene sequence, not timestamps or relation insertion order. Section labels show where each Scene belongs. Unplaced Scenes appear in a separate list using the same updated-date/UUID deterministic order as the M8 tray. No independent rank, completion score or fictional progress percentage is stored.

Highlight leaves all Plot Scenes visible; matching rows gain an accent border and restrained host surface. Filter hides nonmatching Scenes and announces this explicitly outside the collapsible panel. Multiple selected Threads combine with OR; Scene title search further narrows results. Show full Plot clears Thread selection, while the separate title search remains as entered. Selecting a Thread also opens its progression. Removing a selected Thread externally resolves selection against current Entities so an unavailable UUID cannot leave an empty stale filter active.

All Thread search, selection, mode, editing context and pagination are temporary React state, reset on Workspace remount/restart. Section ordering, full-list movement anchors and derived displayed numbers are unchanged. Brainstorm coordinates, groups and layout store are never used or written by Thread projection or membership commands.

## 7. Guide improvements

The integrated English-language Guide follows current product terminology. It teaches concepts first: a Thread is a development, a Section organizes structure and a Scene is one narrative moment. A fantasy example uses The Missing Artifact, Maya and Eli and The Royal Conspiracy, showing how one Scene can advance both a mystery and a relationship without duplication.

Further concise sections explain native creation, association/removal, ordinary Related to semantics, multiple memberships, canonical sequence/Unplaced handling, Highlight versus Filter, Brainstorm independence and writing without Threads. It explicitly supports a personal method instead of prescribing a structure. “Understanding Plot Threads” opens the topic contextually from Plot; existing Guide navigation can reach it elsewhere.

## 8. Portability and readability

The application projection/association helper imports no Obsidian types and is tested independently. React handles presentation and intent; persistence stays behind the existing writer. Native menus, forms and Markdown stay in Obsidian UI/adapters. No Core extraction, host abstraction framework, new package or second Story engine was introduced. Functions use explicit names and focused responsibilities; bidirectional membership and partial writes are documented where their intent matters.

## 13–14. Limits, deferred work and compatibility risks

- Both-direction reading is a documented interpretation of the existing Related to kind for Scene/Thread pairs. Existing custom links with another kind remain generic relationships; M9 cannot infer a user’s custom membership semantics automatically.
- Removing opposite links uses multiple existing writes and can partially fail. Counts and remaining real state are explicit. A concurrent edit in another pane/process can still produce a safe stale-operation error or two opposite generic edges; no cross-note transaction/lock is claimed.
- Unavailable-link warnings intentionally avoid claiming the missing Entity’s former type. Repairing a malformed relation container remains a native Markdown task. Generic Focus preserves existing cross-Workspace behavior; local Thread membership does not include those foreign links.
- The validated native scale is 107 starting Scenes, three UI-created Threads and 37 additional ordinary Threads (39 after one deletion). This is functional coverage, not a general vault benchmark. In-memory scans are retained; EntityIndex is unchanged. Thread choices are paged, lists/progressions scroll, and Scene badges cap visible names. There is no virtualization or new graph canvas.
- Standard host tokens and visible focus states are used, without new motion, gradients or decorative shadows. Tests cover this Linux Obsidian runtime, pointer drag and native keyboard controls. Full screen-reader certification, touch/mobile, other OSes, older Obsidian runtimes and third-party themes remain unverified.
- M9 does not add Thread-specific stages, Character Arcs, completion metrics, a separate timeline/calendar, nesting, thread-local manual order, global undo, AI writing, manuscript tooling, templates, standalone application or a general plugin platform. **M10 has not been started.**
